# Отделен Production Node.js операторски CLI

`scripts/push-node-operator.mjs` използва единствено фиксирания адрес
`https://ba4varov-wheater.vercel.app/api/push-operator`.
Няма настройка за URL, project, fallback към Edge, redirects или retries.
Старият `scripts/push-operator.mjs` остава отделен инструмент.

Тази промяна е само подготовка за преглед. Не стартирайте реалния CLI сега.
`PUSH_NODE_OPERATOR_ENABLED=false` остава непроменено; отказът от сървъра
спира CLI преди потвърждение и изпращане. Няма автоматично активиране.

При бъдещо отделно разрешение за реален тест синтаксисът е:

```text
node scripts/push-node-operator.mjs USER_UUID 5ff76543-ea64-4721-9846-3859621e954f [wind]
```

`USER_UUID` трябва да е изрично избраният акаунт. Единственото допустимо
устройство е новата регистрация на Note 13 Pro, показана по-горе.
CLI не търси устройства и не променя регистрацията. Категорията е ограничена
до съществуващия списък; не се приема произволен payload.

Нужни са интерактивен terminal, съществуващото операторско удостоверение и
текущ access token на администратора. Въвеждат се скрито, само в паметта;
не ги слагайте в argv, environment, файлове или shell history. Live Auth и
текущите DB права се проверяват от съществуващия Node handler при всяка
операция. CLI не декодира JWT като доказателство за права.

Пътят е `prepare → SEND ONE → send → cancel`. При отказ от потвърждение
се прави само cancel. Подготовката трябва да върне същите user/device/category.
След точно `SEND ONE` CLI подава пълната server фраза за избрания акаунт и
устройство. Използва се същият DB permit и server протокол от PR #93;
няма локално заместване на DB разрешението.

При грешка, неизвестен резултат или неуспешен cancel процесът завършва с
ненулев код. Няма втори prepare/send или повторение на cancel. Единствената
следваща заявка след грешка при send е cleanup cancel за известния permit.
При загубен prepare отговор няма известен permit за cancel; DB срокът остава
защитата. При прекъсване на процеса/terminal или насилствено спиране cleanup
не е гарантиран. Не стартирайте повторно след неизвестен резултат.

Отговорите са ограничени по размер и време. HTTP грешки, redirects, невалиден
JSON и неизвестен резултат отказват. Отговори, exceptions, stack traces,
Authorization, permit, endpoint, VAPID и subscription данни не се отпечатват
или записват. Изходът показва само фиксирани съобщения и валидираната селекция.
Приемане от доставчика не доказва доставка до телефона.

Проверки без мрежа:

```text
node tests/unit/push-node-operator-cli.test.mjs
node tests/unit/push-node-operator-tty.test.mjs
```

Тестовете използват само синтетични удостоверения и подменен fetch. Покриват
изключен флаг, права/сесия, грешки, неизвестни резултати, избрано устройство,
конкурентен модел на permit, скрит TTY вход, paste и Ctrl+C. Реалният Node
handler, независими инстанции и атомарният RPC модел се проверяват отделно
от съществуващите `push-node-operator.test.mjs` и CI. Синтетичният модел не е
интеграционен тест срещу Production DB.
